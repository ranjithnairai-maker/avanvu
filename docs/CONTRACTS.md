# Avanvu — Contracts

**Status:** normative. Read with `docs/SPEC.md`. If this file and SPEC disagree, stop and record the conflict in `docs/DECISIONS.md`; do not guess.
**Version:** contracts_v1, 2026-10-11

This file defines the shapes and state machines that several parts of the system depend on: the athlete profile, the intake turn, the session timeline, the quality judge, job and session states, the usage ledger, idempotency, errors, encryption envelopes and analytics events. Implement each one once, in `packages/core`, as Zod schemas plus TypeScript types, and import it everywhere. Never redefine a contract locally.

---

## 1. Conventions

- **IDs:** UUID v7 for database rows (time-ordered). List items inside the profile use an 8-character base-32 `item_id` generated by the server.
- **Time:** all stored timestamps are `timestamptz` in UTC. Events store a local start time plus an IANA time zone (`America/Toronto`). Never store a bare local date as the event start.
- **Text limits:** every athlete-supplied string has a maximum length (given below). The server rejects longer values with `VALIDATION_FAILED`; the model is told the limits.
- **Enums:** lowercase snake_case. Compare model-returned enum values case-insensitively, then normalize (structured outputs do not guarantee enum capitalization).
- **Versions:** every schema has a literal `schema_version`. Stored records keep the version they were written with. Readers support the current version and one prior version.
- **Sensitive fields:** anything marked 🔒 is encrypted with the envelope in §12 before it reaches Postgres, and is never written to logs, analytics, error reports, task payloads or URLs.

## 3. Athlete profile — `athlete_profile_v1` 🔒

The profile is the single source of truth for generation. It is stored as immutable encrypted versions (`app.athlete_profile_versions`), plus a working draft during intake. The event's name (🔒), date, start time, time zone and status are **not** in the profile; they are captured on the event setup screen and live in `app.events`. The profile holds only what the interview adds about the event (stakes, venue).

```ts
type Provenance = 'athlete' | 'edited' | 'default';
// athlete = extracted from the athlete's own words in intake or debrief
// edited  = changed by the athlete on the summary or profile screen
// default = filled by the server (preferences only)

interface TextField { value: string; source: Provenance }
interface ListItem  { item_id: string; value: string; source: Provenance }

interface KeyMoment {
  item_id: string;
  label: string;                 // ≤ 60   e.g. "Kilometre 32"
  description: string;           // ≤ 300
  body_feel: string;             // ≤ 200  may be ""
  realtime_seconds: number | null; // 1–120; how long the action takes in real life, if known
  source: Provenance;
}

interface IfThen { item_id: string; when: string /* ≤ 160 */; then: string /* ≤ 200 */; source: Provenance }

type Level = 'recreational' | 'amateur_competitive' | 'collegiate' | 'semi_pro' | 'elite';
type Anchor = 'thumb_index_press' | 'fist_squeeze' | 'hand_on_chest' | 'none';
type MusicStyle = 'ambient_warm' | 'ambient_airy' | 'low_drone' | 'pulse' | 'voice_only';

interface AthleteProfileV1 {
  schema_version: 'athlete_profile_v1';

  objective: {
    primary: TextField;              // ≤ 200  what they want from this preparation
    process_success: TextField;      // ≤ 300  controllable definition of success
    desired_outcome: TextField | null; // ≤ 200  result they hope for, if any
    why_now: TextField | null;       // ≤ 300
  };

  sport: {
    label: TextField;                // ≤ 60   the athlete's own words ("half Ironman")
    supported_sport_id: string;      // server-owned, from §2
    engine: string;                  // server-owned, from §2
    level: Level;
  };

  event: {
    stakes: TextField | null;        // ≤ 200
    venue: TextField | null;         // ≤ 120
  };

  scene: {
    visual: ListItem[];              // each ≤ 160, max 8
    sounds: ListItem[];              // each ≤ 160, max 6
    smells: ListItem[];              // each ≤ 120, max 4
    weather_temperature: TextField | null; // ≤ 160
    surface_equipment: ListItem[];   // each ≤ 160, max 5
    people_context: ListItem[];      // each ≤ 160, max 5  (sensitive: skippable)
  };

  performance: {
    routine: TextField | null;       // ≤ 400  pre-performance routine
    key_moments: KeyMoment[];        // max 4
    controllables: ListItem[];       // each ≤ 160, max 5
  };

  obstacles: {
    hardest_moment: TextField | null;    // ≤ 300
    negative_self_talk: ListItem[];      // each ≤ 160, max 3, exact words (sensitive: skippable)
    disruptors: ListItem[];              // each ≤ 160, max 4
    past_setback: TextField | null;      // ≤ 300 (sensitive: skippable)
  };

  responses: {
    if_then: IfThen[];               // max 3
    cue_phrase: TextField | null;    // ≤ 40, exact words, used verbatim
  };

  identity: {
    hoped_self: TextField | null;    // ≤ 300
    intention: TextField | null;     // ≤ 160, present tense, exact words, used verbatim
    feared_self: TextField | null;   // ≤ 200 (sensitive: skippable; only used in training sessions)
  };

  outcome: {
    visual: TextField | null;        // ≤ 200
    body: TextField | null;          // ≤ 200
    emotion: TextField | null;       // ≤ 120
    people: ListItem[];              // each ≤ 120, max 4 (sensitive: skippable)
    first_action: TextField | null;  // ≤ 160
    anchor: Anchor;                  // default 'thumb_index_press'
  };

  preferences: {
    perspective: 'first_person' | 'third_person';  // default first_person
    voice_id: string;                // one of the three catalog voices
    music_style: MusicStyle;         // for training sessions; default 'ambient_warm'
    training_length_min: 10 | 15;    // default 15
    primer_length_min: 3 | 5;        // default 5
    feared_self_enabled: boolean;    // default true; false removes the block everywhere
  };

  learning_stage: 1 | 2 | 3;         // server-owned; starts at 1; changed only by confirmed debrief learnings

  field_status: Record<FieldPath, FieldStatus>; // server-owned, see §3.2
}
```

### 3.1 Field paths

`FieldPath` is the closed set below. These are also the only paths the intake model may target.

```
objective.primary            objective.process_success      objective.desired_outcome      objective.why_now
sport.label                  sport.level
event.stakes                 event.venue
scene.visual                 scene.sounds                   scene.smells                   scene.weather_temperature
scene.surface_equipment      scene.people_context
performance.routine          performance.key_moments        performance.controllables
obstacles.hardest_moment     obstacles.negative_self_talk   obstacles.disruptors           obstacles.past_setback
responses.if_then            responses.cue_phrase
identity.hoped_self          identity.intention             identity.feared_self
outcome.visual               outcome.body                   outcome.emotion                outcome.people
outcome.first_action         outcome.anchor
```

Preferences, `sport.supported_sport_id`, `sport.engine`, `learning_stage` and `field_status` are **not** model-writable. Preferences are set with UI controls.

**Sensitive (skippable) paths:** `scene.people_context`, `obstacles.negative_self_talk`, `obstacles.past_setback`, `identity.feared_self`, `outcome.people`. Every prompt for these shows a Skip quick reply. A skipped path is never asked again, never inferred, and never appears in any script.

### 3.2 Field status

```ts
type FieldStatus = 'missing' | 'partial' | 'complete' | 'skipped' | 'unsure';
```

The server computes status after each turn as the **lower** of two values:

1. **Structural status** (deterministic): empty → `missing`; list below its target count or text under 3 words → `partial`; otherwise `complete`. Targets: `scene.visual` 3, `scene.sounds` 2, `performance.key_moments` 2, `responses.if_then` 1, every other list 1.
2. **Quality status** proposed by the model in `field_assessments` (it can lower a field to `partial` when an answer is generic, such as "it's loud"). The model can never raise a field above its structural status.

`skipped` and `unsure` are set only when the athlete chose Skip or Not sure (quick reply or clear statement). They override both values. `unsure` is allowed on any path; `skipped` only on sensitive paths.

### 3.3 Generation minimum

A session can be generated only when all of these are `complete` (or, where noted, have at least the stated content):

- `objective.primary`, `objective.process_success`
- `sport.label` with a server-assigned engine; an `app.events` row with name, local start, and time zone
- `scene.visual` ≥ 1 item, `scene.sounds` ≥ 1 item
- `performance.key_moments` ≥ 2 items with label and description
- `obstacles.hardest_moment`
- `responses.if_then` ≥ 1, `responses.cue_phrase`
- `identity.intention`
- `outcome.visual` or `outcome.body`
- all `preferences` set (defaults count)

Everything else improves the session but is optional. The summary screen cannot be confirmed until the minimum is met; missing minimum fields are shown as inline "Add" rows.

## 4. Intake turn

### 4.1 Request — `POST /v1/intake/turns`

Headers: `Authorization: Bearer <supabase access token>`, `Idempotency-Key: <uuid>`.

```json
{
  "conversation_id": "uuid",
  "client_message_id": "uuid",
  "expected_revision": 12,
  "input_mode": "text",
  "content": "I tend to doubt myself around kilometre 32"
}
```

`input_mode` is `text`, `dictation` or `quick_reply`. `content` ≤ 1,000 characters.

### 4.2 Model output — `intake_turn_output_v1`

Requested with Claude structured outputs (`output_config.format`, type `json_schema`). The schema is designed around the documented structured-output limits: every property is required (no optional parameters), there are no union types, and constraints the API does not enforce (lengths, counts) are checked by Zod on the server.

```json
{
  "assistant_message": "Around kilometre 32, where do you notice the doubt first: in your body, or in the words in your head?",
  "quick_replies": ["Body", "Self-talk", "Both"],
  "profile_updates": [
    { "op": "set", "path": "obstacles.hardest_moment", "item_id": "", "value": "Doubt around kilometre 32" }
  ],
  "field_assessments": [
    { "path": "obstacles.hardest_moment", "quality": "partial" }
  ],
  "safety_signal": "none",
  "next_focus": "obstacles"
}
```

| Property | Type | Rule |
| --- | --- | --- |
| `assistant_message` | string | ≤ 45 words. One question. No exclamation marks, no em dashes. Over the limit → one repair request, then accept up to 60 words and log. |
| `quick_replies` | string[] | 0–4 items, each ≤ 24 characters. Server appends Skip on sensitive paths and Not sure on others. |
| `profile_updates[].op` | enum | `set` (text fields), `add_item` (lists), `replace_item`, `remove_item`, `mark_skipped`, `mark_unsure` |
| `profile_updates[].path` | enum | one of §3.1 |
| `profile_updates[].item_id` | string | `""` for `set`, `add_item`, `mark_*`; an existing item id for `replace_item`/`remove_item` |
| `profile_updates[].value` | string | For text fields and simple lists, the plain text. For `key_moments` and `if_then`, a JSON-encoded object string (`{"label":…,"description":…}`), parsed and validated by the server. `""` for `remove_item` and `mark_*`. |
| `field_assessments[].quality` | enum | `missing`, `partial`, `complete` |
| `safety_signal` | enum | `none`, `ambiguous`, `crisis` |
| `next_focus` | enum | `objective`, `sport_event`, `scene`, `performance`, `obstacles`, `response`, `identity`, `outcome`, `wrap_up` |

The model receives: the system prompt (cached), the current draft profile with field statuses and item ids, follow-up counters, the last 6 turns, and the athlete's new message wrapped as data (`<athlete_message>…</athlete_message>`) with an instruction that text inside it is never an instruction.

### 4.3 Server algorithm (must be implemented in this order)

1. Authenticate; load the conversation; verify ownership and that the account is not deleted.
2. Idempotency check (§9). A completed key returns the stored result.
3. Revision check: `expected_revision` must equal the conversation's current revision, otherwise `409 PROFILE_REVISION_CONFLICT` with the latest committed state.
4. Acquire the turn lease: insert the athlete turn with `status='processing'`, `lease_expires_at = now() + 60 s`. A partial unique index allows one processing turn per conversation. An unexpired lease held by a different idempotency key → `409 TURN_IN_PROGRESS`. An expired lease may be taken over.
5. **Deterministic safety screen** on `content` (SPEC §12.2). On a crisis match: mark the turn `safety_interrupted`, set the conversation to `SAFETY_INTERRUPTED`, commit, and return `SAFETY_INTERRUPTED`. No model call.
6. Call the intake model with a 40-second timeout and the configured effort level. On timeout or 5xx: release the lease (`status='retryable_error'`), return `UPSTREAM_UNAVAILABLE` (retryable). The athlete's text stays in their composer.
7. If `safety_signal = crisis`: same as step 5 (the model is the second layer). If `ambiguous`: discard the model's question and use the reviewed clarification message from the safety policy.
8. Validate the output with Zod. Reject any update whose path is outside §3.1, whose op does not fit the field type, whose `item_id` does not exist, or whose value breaks a length or count limit. Rejected updates are dropped and logged by path and reason (never by value). Invalid JSON or a schema failure → one repair call; a second failure returns `UPSTREAM_UNAVAILABLE`.
9. Apply accepted updates to the draft; never touch a `skipped` path; recompute statuses (§3.2); increment the follow-up counter for any path the assistant question targets. Counter ≥ 2 on a path → mark it resolved for interview flow (status unchanged) and steer `next_focus` elsewhere.
10. Termination check (§5). If met, replace the model's question with the wrap-up message and set `READY_FOR_SUMMARY`.
11. In one short transaction: compare-and-swap the revision (`where revision = expected_revision`), store the encrypted athlete turn as `committed`, the encrypted assistant turn, the new encrypted draft, the new revision, and the idempotency result. Do not hold a transaction open during the model call.
12. Return the committed result.

### 4.4 Response

```json
{
  "revision": 13,
  "state": "AWAITING_USER",
  "assistant_message": "…",
  "quick_replies": ["Body", "Self-talk", "Both", "Not sure"],
  "progress": { "phase": "obstacles", "phases_complete": 4, "phases_total": 9, "minimum_met": false },
  "summary_available": false
}
```

The client reveals `assistant_message` progressively (typing effect) after the response arrives. v1 has no server-sent events.

## 5. Intake conversation state machine

```
ACTIVE ─▶ AWAITING_USER ⇄ PROCESSING_TURN
                │                │
                │                └─▶ RETRYABLE_ERROR ─▶ PROCESSING_TURN
                ▼
        READY_FOR_SUMMARY ─▶ SUMMARY_CONFIRMED ─▶ COMPLETE
any non-terminal ─▶ PAUSED ─▶ (previous state)
any non-terminal ─▶ SAFETY_INTERRUPTED (terminal for this conversation)
```

**Termination (READY_FOR_SUMMARY)** happens at the first of:
- every phase target reached (all non-sensitive fields `complete`, `unsure` or follow-up-exhausted), or
- 40 athlete turns, or
- 15 minutes of active time (time spent waiting on the athlete for more than 2 minutes does not count),

**and** the generation minimum (§3.3) is met. If a cap is hit before the minimum is met, the interview asks only for missing minimum fields (at most 2 asks each), then moves to the summary, where missing minimum fields become inline "Add" rows.

A conversation in `SAFETY_INTERRUPTED` never feeds generation. The athlete can start a new intake later from Home; the new conversation does not copy text from the interrupted one.

## 6. Session timeline — `session_timeline_v1` 🔒

Produced by the script model with structured outputs, validated, then frozen. The renderer reads only this.

```json
{
  "schema_version": "session_timeline_v1",
  "context": "training",
  "engine": "endurance_v1",
  "target_seconds": 900,
  "title": "Patient through 32",
  "items": [
    { "type": "speech",   "block": "arrive",  "text": "Let your eyes close when you're ready.", "duration_ms": 0,    "label": "" },
    { "type": "pause",    "block": "arrive",  "text": "",                                       "duration_ms": 4000, "label": "" },
    { "type": "speech",   "block": "process", "text": "The gun goes. You let the crowd carry you for the first hundred metres.", "duration_ms": 0, "label": "" },
    { "type": "rehearse", "block": "process", "text": "",                                       "duration_ms": 20000, "label": "first 100 m in real time" }
  ]
}
```

- `type`: `speech`, `pause` (elastic silence), `rehearse` (fixed silence for real-time mental rehearsal of an action; never stretched or shrunk).
- `block`: `arrive`, `intention`, `feared_self`, `hoped_self`, `process`, `obstacle`, `outcome_anchor`, `return`. Items appear in block order; a block may be absent only as allowed below.
- All properties are required on every item (empty values as shown) to satisfy structured-output rules. Zod enforces that `text` is non-empty only for `speech`, `duration_ms` > 0 only for `pause`/`rehearse`, and `label` non-empty only for `rehearse`.
- `title` ≤ 40 characters, shown in the library and on the lock screen.

### 6.1 Deterministic validation (all must pass before rendering)

| Rule | Value |
| --- | --- |
| Blocks required | training: all 8 except `feared_self` when the profile has none, it was skipped, or `feared_self_enabled=false`. night_before and primer: never `feared_self`. |
| Block duration | Each block's predicted seconds within 0.5×–1.5× of its share in SPEC §3.3; `feared_self` 15–45 s. |
| Speech item | 1–600 characters; ≤ 3 sentences. |
| Pause | 500–20,000 ms. |
| Rehearse | 1,000–120,000 ms; must follow a speech item in the `process` or `obstacle` block. |
| Consecutive silence | Adjacent pause/rehearse total ≤ 30 s (≤ 45 s in night_before `arrive` and `return`). |
| Silence share | training 30–45 %, night_before 35–55 %, primer 15–35 % of predicted duration. |
| Speech characters | ≤ 12 × `target_seconds` × max speech share (training 0.70, night_before 0.65, primer 0.85); a cost guard equal to 120 words per minute across the largest allowed speech share. |
| Predicted duration | within ±8 % of target. Predicted speech seconds = words ÷ the voice's calibrated words-per-minute (`app.voice_catalog.wpm`) × 60. |
| Verbatim content | `cue_phrase` appears verbatim at least once in `obstacle`; `intention` appears verbatim in `intention` and again in `return`. At least one confirmed if-then plan is rehearsed in `obstacle`. |
| Style | No `!`, no em dash (—), no en dash used as a dash. Second person, present tense, except intention and self-talk lines, which are first person. |
| Banned content (word lists + patterns, maintained in `packages/core/safety/lexicon.ts`) | manifestation language; guaranteed or promised results; instructions to ignore or push through pain; weight-loss, dieting, restriction, purging or weight-cutting language (the bare word "weight" is allowed: weightlifting, bodyweight, equipment weight); medical or diagnostic claims |
| Skipped and empty | No text derived from a skipped or `unsure` path (checked by the judge; see §7). |

On failure: one constrained repair call that receives the failing rule ids (never the athlete text in logs). A second failure fails the job (§8) and reverses the reservation.

### 6.2 Duration fitting after synthesis

After all speech is synthesized, the renderer knows the real speech durations. It then scales every `pause` item by a single factor f, with 0.6 ≤ f ≤ 1.5 and each pause clamped to 500–20,000 ms, to bring the total as close as possible to `target_seconds` (aim ±2 %). `rehearse` items are never changed. If the fitted total is within ±10 % of target, render. Otherwise fail with `DURATION_UNFITTABLE` (this signals a word-budget bug; it is never fixed by re-synthesizing speech).

## 7. Quality judge — `script_judgement_v1`

A second, cheaper model call (`LLM_MODEL_JUDGE`) runs after deterministic validation passes. It receives the confirmed profile (with skipped and unsure paths listed explicitly), the timeline text and the engine, and returns:

```json
{
  "checks": [
    { "id": "no_invented_facts",       "pass": true,  "note": "" },
    { "id": "no_skipped_content",      "pass": true,  "note": "" },
    { "id": "no_technique_instruction","pass": true,  "note": "" },
    { "id": "no_unsafe_guidance",      "pass": true,  "note": "" },
    { "id": "process_over_outcome",    "pass": true,  "note": "" },
    { "id": "if_then_rehearsed",       "pass": true,  "note": "" },
    { "id": "tone_and_voice",          "pass": true,  "note": "" },
    { "id": "engine_structure",        "pass": true,  "note": "" }
  ]
}
```

`note` ≤ 200 characters and must not quote the athlete. Any failing check triggers the single repair call (shared with §6.1, so there is at most one repair per job). Judge failures are counted per check id for the eval dashboard. The judge is a quality gate, not a safety guarantee; deterministic rules in §6.1 always run.

## 8. Session and render states

### 8.1 Session state

```
reserved ─▶ queued ─▶ generating_script ─▶ validating ─▶ synthesizing ─▶ mixing ─▶ uploading ─▶ ready
   │           │
   └───────────┴─▶ canceled        (athlete cancel; only from reserved or queued; reverses the reservation)
any non-terminal ─▶ failed          (attempts exhausted or non-retryable error; reverses the reservation)
```

- The client sees a simplified status: `preparing` (reserved through validating), `voicing` (synthesizing through uploading), `ready`, `failed`, `canceled`.
- Once `generating_script` starts, the athlete cannot cancel; they can delete the session after it is ready (allowance stays consumed).
- Only the worker moves a session past `queued`. Every transition is a compare-and-swap on `(id, state, attempt)`.

### 8.2 Render job, attempts and checkpoints

`app.render_jobs` holds `attempt`, `lease_owner`, `lease_expires_at`, `stage`, `last_error_code`. The worker:

1. Verifies the Cloud Tasks OIDC token (audience = worker URL, email = tasks invoker service account).
2. Takes the lease: `update … set lease_owner=$me, lease_expires_at=now()+120s where id=$job and state not in (terminal) and (lease_expires_at is null or lease_expires_at < now()) returning *`. No row → return 200 (another attempt owns it or it is finished).
3. Heartbeats every 30 s (extends the lease by 120 s).
4. Checkpoints so a retry never pays twice:
   - the validated, encrypted timeline is stored before synthesis; a retry that finds it skips generation and validation;
   - each synthesized speech chunk is written to `jobs/{job_id}/chunks/{sha256(text|voice|model|settings)}.wav` in a private bucket; a retry reuses existing chunks; the `jobs/{job_id}/` prefix is deleted when the job reaches a terminal state, and a daily sweep deletes any older than 24 h;
   - the final file is uploaded to the deterministic path `audio/{user_id}/{session_id}/{render_version}.m4a`.
5. Final transition in one transaction: session `ready`, `audio_path`, `duration_ms`, `sha256`, `bytes`; usage ledger `commit` entry; outbox row for the "session ready" push. The push is sent only on this first transition to `ready`.
6. Returns non-2xx only for retryable errors (Cloud Tasks retries). Non-retryable errors set `failed`, write the reversal, and return 200.

Retryable: vendor 429/5xx, network timeouts, lease lost. Non-retryable: validation failed after repair, `DURATION_UNFITTABLE`, entitlement revoked before generation started, profile version missing.

## 9. Idempotency

Every mutating endpoint requires `Idempotency-Key` (UUID). Stored in `app.idempotency_keys(user_id, endpoint, key, request_hash, status, response_code, response_body_ref, created_at, expires_at)` with a unique constraint on `(user_id, endpoint, key)`; rows expire after 7 days.

| Situation | Result |
| --- | --- |
| New key | Process; store result |
| Same key, same body hash, completed | Return the stored response |
| Same key, same body, still processing | `409 REQUEST_IN_PROGRESS` with `retry_after_ms` |
| Same key, different body | `409 IDEMPOTENCY_KEY_REUSED` |

Database unique constraints are the final defense (for example `usage_ledger.idempotency_key`, `sessions.creation_key`, `webhook_events.vendor_event_id`).

## 10. Error contract

```json
{ "error": { "code": "ALLOWANCE_EXHAUSTED", "message": "You've used this month's new sessions.", "retryable": false, "request_id": "req_…" } }
```

`message` is safe to show to the athlete. Vendor error text is never returned.

| Code | HTTP | Retryable |
| --- | --- | --- |
| `UNAUTHENTICATED` | 401 | no |
| `ACCOUNT_DELETED` | 401 | no |
| `AGE_REQUIREMENT_NOT_MET` | 403 | no |
| `FORBIDDEN` | 403 | no |
| `NOT_FOUND` | 404 | no |
| `VALIDATION_FAILED` | 422 | no |
| `UNSUPPORTED_SPORT` | 422 | no |
| `IDEMPOTENCY_KEY_REUSED` | 409 | no |
| `REQUEST_IN_PROGRESS` | 409 | yes |
| `PROFILE_REVISION_CONFLICT` | 409 | no (refetch) |
| `TURN_IN_PROGRESS` | 409 | yes |
| `SAFETY_INTERRUPTED` | 409 | no |
| `MINIMUM_PROFILE_INCOMPLETE` | 422 | no |
| `ENTITLEMENT_REQUIRED` | 402 | no |
| `ALLOWANCE_EXHAUSTED` | 402 | no |

## 11. Usage ledger

`app.usage_ledger` is append-only. Rows are never updated or deleted except by account deletion.

| Column | Meaning |
| --- | --- |
| `allowance_type` | `free_training`, `free_primer`, `pro` |
| `bucket_start`, `bucket_end` | The allowance window (see below) |
| `entry_type` | `grant` (+N), `reserve` (−1), `reverse` (+1), `commit` (0, marks success for audit) |
| `quantity` | signed integer as above |
| `session_id` | for reserve, reverse, commit |
| `idempotency_key` | unique; e.g. `grant:{user}:{bucket_start}`, `reserve:{session_id}` |

**Buckets**
- Free: one lifetime bucket from account creation, with `grant +1 free_training` and `grant +1 free_primer` written at account creation. The `free_primer` grant can be consumed only by the scheduler for an event's planned primer item (free users' on-demand primers use the bundled backup primer), so nothing else can use it up and no advance reservation is needed.
- Pro (monthly or annual): monthly buckets anchored to the entitlement's original purchase timestamp (UTC). Bucket *k* = [anchor + *k* months, anchor + *k*+1 months); when the anchor day does not exist in a month, use the month's last day at the anchor time. The grant for a bucket is written lazily the first time it is needed while the entitlement is active.
- Trial: the trial period is one bucket granted `TRIAL_SESSION_ALLOWANCE` (config; see DECISIONS D-17). On conversion, a top-up grant of `PRO_MONTHLY_ALLOWANCE − TRIAL_SESSION_ALLOWANCE` is written to the current bucket.
- No rollover. A lapsed, refunded or revoked entitlement stops new grants immediately; existing reservations already in progress complete.

**Availability**

```
available(type, bucket) = Σ quantity for that type and bucket
held_for_events         = number of night_before + primer program items scheduled to start generation inside the current bucket and not yet reserved
available_for_on_demand = available(pro, current) − held_for_events      // shown as "2 sessions held for race day"
```

`held_for_events` applies to Pro only; the free primer is protected by its type restriction above.

## 12. Encryption envelope

Sensitive values are stored as `bytea`:

```
byte 0      : format version (0x01)
bytes 1–4   : data-key version (uint32, big-endian)
bytes 5–16  : 96-bit random nonce
bytes 17–…  : AES-256-GCM ciphertext followed by the 16-byte tag
```

Additional authenticated data (AAD) = UTF-8 of `"{table}:{column}:{row_id}:{user_id}:{schema_version}"`. A ciphertext copied to another row or user fails to decrypt.

Data keys: one 256-bit data key per user, generated on first sensitive write, wrapped by Cloud KMS (`KMS_KEY_NAME`) with AAD `user:{user_id}`, stored in `app.user_data_keys(user_id, key_version, wrapped_key, kms_key_version, created_at)`. Unwrapped keys are cached in process memory for at most 5 minutes (LRU, max 500 entries) and never logged or serialized. KMS rotates its key version every 90 days; old versions stay enabled for unwrapping. Implementation lives only in `packages/core/crypto` and uses WebCrypto (`crypto.subtle`), with round-trip, tamper, wrong-AAD and wrong-key tests.
